# Arong Content Engine

一个用于把个人思考或真实经历，逐步做成文章、单一竖版长视频和多平台发布包的 Codex Skill。

它强调三件事：

- 先确认选题和事实边界，再写正文；
- AI 检测默认只诊断，修改必须经过用户确认；
- 标题、开头、封面分别决定，不把它们强绑成一套方案。

## 这是什么

这是一个**核心工作流 Skill**，适合内容创作者把自己的笔记、经历和观点转为可审阅的内容资产。

它不包含任何人的知识库、账号、声音参考、平台密码或收益承诺；也不自动发布内容。

## 安装

仓库发布后可使用：

```bash
npx -y skills add alonzodeheart-cmd/arong-content-engine -g --all
```

或者把整个仓库复制到 Codex 的 skills 目录。

## 使用示例

```text
使用 $arong-content-engine：
我想把这段经历做成一篇文章和一条 3–5 分钟竖版视频。
```

```text
使用 $arong-content-engine：
从我的思考库推荐 5 个选题，但先不要写文章。
```

## 核心流程

1. 选题：用户给题，或只读搜索用户明确指定的个人资料。
2. 诊断：确定受众、冲突、证据边界和行动落点。
3. 共创：只问影响方向的关键问题，不让用户逐段供稿。
4. 审阅：文章、视频稿均需用户确认；AI 检测先留报告再讨论修改。
5. 独立决策：标题、开头、封面分别输出和确认。
6. 制作：只生成一版 9:16、3–5 分钟长视频；本地 Markdown 是事实源。
7. 发布：生成发布包，用户自行发布；之后基于真实数据复盘。

## 可选集成

本 Skill 可以搭配以下能力，但不强制：

- 标题、开头、封面诊断 Skill；
- 本地 TTS、字幕对齐、Remotion 或其他视频渲染工具；
- 飞书、Notion 或本地 Markdown 作为审阅镜像。

没有这些工具时，仍可完成选题、文章、视频稿、分镜和发布文案。

## 个人资料如何接入

不要把个人文件路径写死进 Skill。复制 [source-map.example.md](references/source-map.example.md)，在自己的私有目录填写来源；搜索默认只读，除非你明确要求收录或整理。

## 边界

- 不自动发布、发消息、购买、投放或收费。
- 不把 AI 推导写成用户经历。
- 不保证流量、收益或平台结果。
- 对平台规则、价格、产品能力等易变化信息，使用前应核对当前官方信息。
