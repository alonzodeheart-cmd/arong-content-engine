# Arong Content Engine

一个用于把个人思考或真实经历，逐步做成文章、单一竖版长视频和多平台发布包的 Codex Skill。

它强调三件事：

- 先确认选题和事实边界，再写正文；
- AI 检测默认只诊断，修改必须经过用户确认；
- 标题、开头、封面分别决定，不把它们强绑成一套方案。
- 封面默认采用“主题背景压暗 + 2–4 行大字”；视频先做 20–30 秒 Motion-first 预览，通过后才渲染长片。

## 这是什么

这是一个**核心工作流 Skill**，适合内容创作者把自己的笔记、经历和观点转为可审阅的内容资产。

它不包含任何人的知识库、账号、声音参考、平台密码或收益承诺；也不自动发布内容。

## 安装

仓库发布后可使用：

```bash
npx -y skills add alonzodeheart-cmd/arong-content-engine -g --all
```

或者把整个仓库复制到 Codex 的 skills 目录。

## 使用示例

```text
使用 $arong-content-engine：
我想把这段经历做成一篇文章和一条 3–5 分钟竖版视频。
```

```text
使用 $arong-content-engine：
从我的思考库推荐 5 个选题，但先不要写文章。
```

## 核心流程

1. 选题：用户给题，或只读搜索用户明确指定的个人资料。
2. 诊断：确定受众、冲突、证据边界和行动落点。
3. 共创：只问影响方向的关键问题，不让用户逐段供稿。
4. 审阅：文章、视频稿均需用户确认；AI 检测先留报告再讨论修改。
5. 公众号排版：文章确认后生成一份可粘贴 HTML；只改排版，不改 Markdown 正文。
6. 独立决策：标题、开头、封面分别输出和确认，并分别调用对应专项检查。
7. 视觉预览：先生成大字封面和 20–30 秒动态测试片，检查 Anti-PPT 硬门。
8. 制作：预览经用户确认后，只生成一版 9:16、3–5 分钟长视频；本地 Markdown 是事实源。
9. 发布：生成发布包，用户自行发布；之后基于真实数据复盘。

## DB Skill 的整合方式

它的重点是把一整条内容流程串起来；如果安装了兼容的 DB Skill，下列节点必须单独调用并留下报告：

- `dbs-ai-check`：文章初稿和视频稿的 AI 写作特征检查；
- `dbs-xhs-title`：标题候选与选择；
- `dbs-hook`：前 5 秒开头诊断与候选；
- `dbs-cover`：封面钩子和视觉方向；
- `dbs-script-flow`：视频逐字稿的逻辑衔接检查。
- `dbs-wechat-html`：文章确认后的微信公众号粘贴版 HTML；不改写正文。

如果本机安装了 [`rn-motion-director`](https://github.com/Pluviobyte/rnskill/tree/main/skills/rn-motion-director)，可在视频阶段调用它做运动命题和 Anti-PPT 复核；没有安装时使用仓库内置的 [视觉生产契约](references/visual-production-contract.md)，不会假装已经调用外部 Skill。

没有安装这些专项 Skill 时，核心流程仍可运行，但 Skill 会明确标记“该检查未执行”，不会假装已经完成。

本地 TTS、字幕对齐、Remotion 或其他视频渲染工具，以及飞书、Notion 等审阅镜像仍然是可选集成。

## 个人资料如何接入

不要把个人文件路径写死进 Skill。复制 [source-map.example.md](references/source-map.example.md)，在自己的私有目录填写来源；搜索默认只读，除非你明确要求收录或整理。

## 边界

- 不自动发布、发消息、购买、投放或收费。
- 不把 AI 推导写成用户经历。
- 不保证流量、收益或平台结果。
- 对平台规则、价格、产品能力等易变化信息，使用前应核对当前官方信息。
